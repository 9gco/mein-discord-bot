fix(deploy): Einstiegspunkt fuer Hosts mit fixem Startbefehl

Monkey Network laesst den Startup-Befehl nicht aendern. Das NodeJS-Egg
startet daher immer `node <Hauptdatei>` und kann kein Bash. Statt
deploy/pterodactyl/start.sh bekommt das Repository deshalb main.js:

- baut dist/ bei Bedarf, weil dist/ in .gitignore liegt und nach jedem
  `git pull` fehlt
- installiert vorher mit --include=dev nach, weil das Egg zuvor nur
  `npm install --production` ausfuehrt und TypeScript sonst fehlt

Zusaetzlich zwei Fehler im Update-Pfad behoben:

- execFile findet unter Windows kein "npm", weil es dort npm.cmd heisst.
  Das ist im Container harmlos, wuerde aber jeden lokalen Test brechen.
- Das Selbst-Update kopierte package.json und package-lock.json in den
  Arbeitsbaum. Das Egg zieht bei jedem Start per `git pull` nach und bricht
  bei lokalen Aenderungen ab. Steht ein .git im Anwendungsverzeichnis,
  wird der Baum jetzt per `git reset --hard` exakt auf die neue Revision
  gesetzt; die Dateien werden nur noch ohne Repository kopiert.

tsconfig: "incremental" abgeschaltet. Die tsbuildinfo landete im
Projektwurzelverzeichnis, waehrend die Ausgabe in dist/ liegt. Wird dist/
geloescht oder getauscht, glaubt tsc, alles sei kompiliert, und erzeugt
eine unvollstaendige Ausgabe - im Container also ein Bot, der beim ersten
Start nicht startet. Testdateien werden nicht mehr nach dist/ gebaut.
